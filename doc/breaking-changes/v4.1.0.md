# Migration guide: 4.1.0

This release aligns the viewer, event delivery, webhook sinks, and cache around the current `CurlConfig` and sink APIs. Continue to use the [4.0.0 migration guide](v4.0.0.md) for the earlier interceptor rewrite; the changes below describe the additional 4.1.0 removals and behavior.

## Viewer and bubble

`showCurlViewer(context)` opens one full-screen viewer. Dialog and bottom-sheet presentation modes and viewer filter-rule editing have been removed. Selecting a record opens the retained detail inspector with Overview, Headers, Response Body, and cURL tabs. `CurlDetailViewer.show(context, entry)` is available for direct presentation.

Install `CurlBubble` in `MaterialApp.builder` with the same navigator key used by `MaterialApp`:

```dart
final navigatorKey = GlobalKey<NavigatorState>();

MaterialApp(
  navigatorKey: navigatorKey,
  builder: (context, child) => CurlBubble(
    navigatorKey: navigatorKey,
    child: child ?? const SizedBox.shrink(),
  ),
  home: const HomePage(),
)
```

The bubble opens the full-screen viewer as a temporary route while the app page stays mounted. The old `BubbleOverlay`, `BubbleStyle`, and `BubbleOverlayController` APIs are removed.

Viewer search, date, and status selections are session-only. The `enablePersistence` option and persisted viewer preferences have been removed. Clear All deletes records only from the active cache box.

## Request path filtering removal

Request path filtering and mock responses have been removed. `FilterOptions`, filter rules, matching utilities, the filter management service, and the filter editor are no longer public APIs. Use Dio's own interceptors for request routing or response mocking. Use `StatusFilterSink` when the goal is to filter which completed events reach a sink:

```dart
StatusFilterSink(
  DiscordSink(name: 'server-errors', webhookUrl: webhookUrl),
  allowedStatuses: const {ResponseStatus.serverError},
)
```

## Delivery and webhook changes

The retry policy and retry configuration have been removed. The relay dispatches asynchronously, deduplicates according to `RelayOptions`, and uses a per-sink circuit breaker that opens after five consecutive sink failures. Sink failures are not retried by the package.

Discord and Telegram sinks each target one endpoint. Replace list-based destination configuration with one sink per endpoint and give each sink a unique `name`:

```dart
final sinks = [
  DiscordSink(name: 'discord-primary', webhookUrl: discordUrl),
  DiscordSink(name: 'discord-secondary', webhookUrl: backupDiscordUrl),
  TelegramSink(name: 'telegram-alerts', botToken: token, chatId: chatId),
];
```

When `dio` is omitted, webhook sinks share the package-owned Dio client. An injected Dio remains owned by the caller. Authorization, Cookie, and Set-Cookie headers are redacted by default; `redactAuthHeaders: false` opts out.

## Cache encryption is opt-in

`CachedCurlService.init()` now opens an unencrypted Hive CE cache and does not require `flutter_secure_storage`. To enable encryption, provide a stable 32-byte key and manage its secure storage in your application:

```dart
await CachedCurlService.init(encryptionKey: encryptionKey);
```

The package no longer generates, stores, or restores an encryption key. The same key must be supplied on later launches to open the encrypted cache. Invalid keys and failed opens leave existing data intact.

The cache box name and encryption setup changed from earlier beta builds. Existing `cachedCurlBox` data is not migrated automatically; it is left on disk, but the new cache service does not open it. Back up or export records before upgrading if that old cache must be retained.

## Public exports

The package barrel exports `CurlViewer`, `showCurlViewer`, `CurlBubble`, `CurlDetailViewer`, and the JSON tree types (`JsonTreeViewer`, `JsonTreeController`, `JsonTreeTheme`, and `FlatJsonNode`). Removed filter-rule, bubble-overlay, and retry-policy APIs are not exported.
