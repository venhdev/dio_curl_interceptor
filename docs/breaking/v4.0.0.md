# Migration guide: 4.0.0

`dio_curl_interceptor` 4.0 is a breaking rewrite. The old `CurlInterceptor`,
`CurlInterceptorV2`, and `CurlInterceptorFactory` are gone. A single
`DioCurlInterceptor` replaces them, with three peer layers
(`DioCurlInterceptor` → `CurlRelay` → sinks) wired up explicitly via one
`CurlConfig` value object.

## Quick mapping

| Before (3.x)                                  | After (4.0)                                                  |
|-----------------------------------------------|--------------------------------------------------------------|
| `CurlInterceptor(...)`                        | `DioCurlInterceptor(config: CurlConfig(...))`               |
| `CurlInterceptorV2(...)`                      | _removed — its retry / circuit-breaker / dedupe live in the relay_ |
| `CurlInterceptorFactory.create(...)`          | _removed — `CurlConfig.sinks` is explicit_                  |
| `CurlInterceptorFactory.withFilters(...)`     | `DioCurlInterceptor(config: CurlConfig(filterOptions: ...))` |
| `CurlInterceptor.webhookInspectors: [...]`    | `CurlConfig(sinks: [...])`                                  |
| `DiscordInspector(...)`                       | `DiscordSink(webhookUrls: ...)` _(deprecated alias deleted in 5.0)_ |
| `TelegramInspector(...)`                      | `TelegramSink(botToken: ..., chatIds: [...])` _(deprecated alias deleted in 5.0)_ |
| `WebhookInspectorBase`                        | _deprecated — use `Sink` / `CurlSink` / `MessageSink`_      |
| implicit retry / circuit-breaker (V2 default)  | now built into `CurlRelay` and tunable via `RelayOptions`    |

## Minimal migration

**Before:**

```dart
final dio = Dio();
dio.interceptors.add(CurlInterceptor(
  curlOptions: CurlOptions(
    behavior: CurlBehavior.chronological,
    onResponse: ResponseDetails(
      visible: true,
      requestBody: true,
      responseBody: true,
      limitResponseBody: 4096,
    ),
  ),
));
```

**After:**

```dart
final dio = Dio();
dio.interceptors.add(DioCurlInterceptor(
  config: CurlConfig(
    behavior: CurlBehavior.chronological,
    onResponse: const ResponseDetails(
      visible: true,
      requestBody: true,
      responseBody: true,
      limitResponseBody: 4096,
    ),
  ),
));
```

That's the entire diff for the no-webhook case. Defaults turn on retries,
circuit breakers, and 1-minute dedupe automatically; opt out via
`relayOptions: RelayOptions.disabled()` (or pass your own flags).

## Webhook migration (Discord)

**Before:**

```dart
dio.interceptors.add(CurlInterceptor(
  webhookInspectors: [
    DiscordInspector(
      webhookUrls: ['https://discord.com/api/webhooks/...'],
      includeUrls: ['api.example.com'],
      excludeUrls: ['/healthz'],
    ),
  ],
));
```

**After:**

```dart
dio.interceptors.add(DioCurlInterceptor(
  config: CurlConfig(
    sinks: [
      DiscordSink(
        webhookUrls: ['https://discord.com/api/webhooks/...'],
      ),
    ],
  ),
));
```

`DiscordSink` redacts `Authorization`, `Cookie`, `Set-Cookie` headers from
the outbound payload — set `requestHeaders: true` no longer affects this.

## Webhook migration (Telegram)

**Before:**

```dart
dio.interceptors.add(CurlInterceptor(
  webhookInspectors: [
    TelegramInspector(
      botToken: 'YOUR_BOT_TOKEN',
      chatIds: [-1003019608685],
    ),
  ],
));
```

**After:**

```dart
dio.interceptors.add(DioCurlInterceptor(
  config: CurlConfig(
    sinks: [
      TelegramSink(
        botToken: 'YOUR_BOT_TOKEN',
        chatIds: ['-1003019608685'], // note: String, not int
      ),
    ],
  ),
));
```

`chatIds` is `List<String>` (was `List<dynamic>`).

## Path filtering

**Before:**

```dart
final filterOptions = FilterOptions(/* rules... */);
dio.interceptors.add(CurlInterceptorFactory.withFilters(filterOptions: filterOptions));
```

**After:**

```dart
final filterOptions = FilterOptions(/* rules... */);
dio.interceptors.add(DioCurlInterceptor(
  config: CurlConfig(filterOptions: filterOptions),
));
```

## Status filtering

The 3.x `CurlOptions(inspectionStatus: [...])` knob is gone. Status-code
filtering lives at the **sink layer** in 4.0 — Layer 1 (`DioCurlInterceptor`)
must not switch on status, and Layer 2 (`CurlRelay`) only wraps. Wrap the
target sink in `StatusFilterSink` and pass an allow-list:

**Before (3.x):**

```dart
CurlInterceptor(curlOptions: CurlOptions(
  inspectionStatus: [ResponseStatus.clientError, ResponseStatus.serverError],
))
```

**After (4.0):**

```dart
DioCurlInterceptor(config: CurlConfig(
  sinks: [
    StatusFilterSink(
      DiscordSink(webhookUrls: ['…']),
      allowedStatuses: {ResponseStatus.clientError, ResponseStatus.serverError},
    ),
  ],
))
```

Notes:

- `RequestCurlEvent` is always forwarded — the request has not seen a
  response yet, so there is nothing to filter on.
- `ResponseCurlEvent` is forwarded iff `ResponseStatus.fromCode(response.statusCode)`
  is in the allow-list. The interceptor's `-1` sentinel for missing codes
  resolves to `ResponseStatus.unknown`, which is dropped unless the
  allow-list contains it.
- `ErrorCurlEvent` is forwarded iff `ErrorInfo.statusCode` (nullable)
  resolves to an allowed bucket. Errors with no status code (network
  failure, cancellation, DNS error) are treated as `unknown` — add it
  to the allow-list if you want them kept.
- `sendMessage` always passes through — manual messages carry no status.

If you want the same defaults the 3.x `defaultInspectionStatus` constant
delivered (informational, redirection, clientError, serverError — i.e.
everything except the noisy 2xx), omit `allowedStatuses`: that's the
wrapper's built-in default.

## Sending manual messages (new in 4.0)

`interceptor.sendMessage(...)` posts plain text to every `MessageSink` (or
a `targetSinks` subset) with no HTTP request required. Useful for app-start
hooks, button taps, navigation events, error reporting that has nothing to
do with a request.

```dart
await interceptor.sendMessage('App started');
await interceptor.sendMessage(
  'checkout completed',
  targetSinks: ['Discord'], // only sinks whose `name == 'Discord'` fire
);
```

If you were using `DiscordInspector.sendMessage(...)` before, call
`interceptor.sendMessage(...)` instead — same effect, shared circuit
breaker and retry pipeline.

## Deprecated in 4.0, removed in 5.0

`discord_inspector.dart`, `telegram_inspector.dart`,
`webhook_inspector_base.dart` carry a deprecation banner and keep compiling.
They will be deleted in 5.0.0. Migrate before then.

## Logging

3.x used `dart:developer.log`. 4.0 uses `package:logging`:

```dart
import 'package:logging/logging.dart';

Logger('CurlInterceptor').onRecord.listen((r) {
  // r.level, r.message, r.error, r.stackTrace
});
```

Use `Level.FINE` to see dedupe hits, retry attempts, breaker state
transitions, and orphan-stopwatch sweeps.
